# dm-notifier

A lightweight Docker container that watches for Docker events on a user's server and forwards them to the Docker Manager Pro backend for push notification delivery.

## How It Works

1. Mounts the Docker socket in **read-only** mode
2. Watches `docker events` for meaningful container events (start/stop/die/restart/oom/kill)
3. Filters out noise events (exec, attach, detach, etc.)
4. POSTs each event to the backend with authentication via pairing token
5. Backend fans out FCM push notifications to all the user's devices

## Building

```bash
docker build -t ghcr.io/thesobersobber/dm-notifier:latest .
```

## Running (manual)

```bash
docker run -d \
  --name dm-notifier \
  --restart unless-stopped \
  -v /var/run/docker.sock:/var/run/docker.sock:ro \
  -e PAIRING_TOKEN=<token> \
  -e BACKEND_URL=https://your-backend.example.com/api \
  -e SERVER_ID=<server-id> \
  --memory=64m \
  --cpus=0.1 \
  ghcr.io/thesobersobber/dm-notifier:latest
```

> **Note:** In production, the Docker Manager app deploys this container automatically via SSH — users don't need to run this manually.

## Environment Variables

| Variable | Required | Description |
|---|---|---|
| `PAIRING_TOKEN` | ✅ | Authentication token (generated by the app) |
| `BACKEND_URL` | ✅ | Backend API base URL |
| `SERVER_ID` | ✅ | Unique identifier for this server |
| `EVENT_TYPES` | ❌ | Event types to watch (default: `container`) |

## Resource Usage

- **Memory limit:** 64MB
- **CPU limit:** 0.1 cores (10%)
- **Image size:** ~60MB (based on docker:24-cli Alpine)
- **Network:** Minimal — only sends small JSON payloads on events

## Security

- Docker socket is mounted **read-only** — the notifier cannot modify containers
- Communication with the backend uses bearer token authentication
- The pairing token is short-lived and tied to a specific user + server
